## 0. 为什么需要这份文档

本项目最高等级的风险（方案 §12-RK1）不是技术风险，而是**口径污染对外披露**：

`store` 表有 500 行，但实测只有 **store_id = 1、2** 两家有业务数据（inventory 2270/2311 条，customer 326/273 个），其余 498 家零库存零客户。若披露报告写「本公司拥有 500 家门店」，这是**实质性错误陈述**。

技术手段无法判定"哪个才是业务真实的门店数"——**只有业务方能定义**。因此本文档必须签字。

## 1. 门店有效性口径（最高优先级）

### 1.1 三态定义

| 状态 | 判定规则 | 当前数据实测 |
|---|---|---|
| `ACTIVE` | 有 inventory **且** 有 customer **且** 统计期间内有 payment | store_id 1、2 |
| `DORMANT` | 有 inventory 但统计期间内无 payment | 0 家 |
| `EXCLUDED` | 无 inventory **且** 无 customer | 498 家（store_id 0、3~499） |

> ⚠️ **实施期发现的规格缺口**：上述三态**未覆盖「无 inventory 但有 customer」的组合**。
> 实现中已显式增加第四态 `UNCLASSIFIED` 并由 DQ 规则 `STORE_UNCLASSIFIED`（WARN）告警，
> 而非静默归入某一态造成口径错误。**待业务方在 §1.3-B4 中裁定其归属。**

### 1.2 强制约束

- **任何层的门店口径必须来自 `dw.dim_store`，禁止任何地方直接 `FROM store`。**
- 对外披露的「门店数」= `count(*) WHERE store_status = 'ACTIVE'`。
- 变更本定义必须新增 `rpt_metric_def` 版本号，不得原地修改。

### 1.3 待业务方确认项

| 编号 | 待确认 | 备选 |
|---|---|---|
| B1 | `EXCLUDED` 的 498 家是脏数据还是"已签约未开业"？ | (a) 脏数据，应清理 / (b) 筹建中门店，需单列口径 |
| B2 | `DORMANT` 门店是否计入对外披露的门店数？ | (a) 计入 / (b) 不计入 / (c) 单列附注 |
| B3 | 「统计期间内有 payment」的期间取值 | (a) 报告期 / (b) 最近 12 个月 / (c) 开业至今 |
| **B4** | **「无 inventory 但有 customer」的门店归属**（实施期发现的规格缺口，现落为 `UNCLASSIFIED`） | (a) 归入 `EXCLUDED` / (b) 归入 `DORMANT` / (c) 保留独立态并单列附注 |

## 2. 统一分析截止日

### 2.1 问题

实测：`rental` 最大日期 **2022-08-23**，而 `payment` 最大日期 **2022-07-27**。若不统一截止日，2022-08 会呈现「有租赁、零收入」——在趋势图上就是一条**假的断崖式收入下滑**，而高层会据此做决策。

### 2.2 口径

```
analysis_cutoff = LEAST( max(payment.payment_date), max(rental.rental_date) )
```

- 所有层的统计区间上界不得超过 `analysis_cutoff`。
- 超出部分的数据仍进 DWD（不丢数据），但 DWS/ADS 聚合排除，并由 DQ 规则 `DATE_RANGE_MISMATCH`（CRITICAL）告警。

## 3. 期间完整性

### 3.1 问题

实测首末月不完整：2022-01 从 **23 日**起（723 笔），2022-07 到 **27 日**止（2334 笔）。

直接算环比会得到假数字。实测 MoM：

| 月份 | 金额 | MoM | 说明 |
|---|---|---|---|
| 2022-01 | 3094.78 | — | 仅 23–31 日 |
| **2022-02** | 10164.97 | **+228.46%** | ← **假暴增**，因 1 月不完整 |
| 2022-03 | 11413.86 | +12.29% | 正常 |
| 2022-04 | 10759.52 | −5.73% | 正常 |
| 2022-05 | 11347.28 | +5.46% | 正常 |
| 2022-06 | 10923.45 | −3.74% | 正常 |
| **2022-07** | 9712.65 | **−11.08%** | ← **假下滑**，因 7 月不完整 |

### 3.2 口径

- DWS 每行必须带 `is_complete_period boolean`。
- **`is_complete_period = false` 的期间，环比/同比一律返回 NULL**，报表显示「数据不完整」。
- DQ 规则 `PERIOD_INCOMPLETE`（WARN）标记。

## 4. COUNT 口径（A 兼容模式陷阱）

### 4.1 问题

数据库为 Oracle 兼容模式（`datcompatibility = A`），**空字符串 ≡ NULL**。因此：

- `COUNT(*)` 统计所有行
- `COUNT(col)` **跳过** `col` 为 NULL 或空串的行

两者在本库上口径**不同**。受影响列包括 `address.phone`、`address.district`（本移植版已改为可空）、`customer.email`、`staff.email`、`staff.password`。

### 4.2 口径

| 指标类型 | 必须使用 | 理由 |
|---|---|---|
| 记录数（笔数、单量） | `COUNT(*)` | 不受列空值影响 |
| 有效值计数（如"已填手机号的客户数"） | `COUNT(col)` | 语义即为"非空计数" |
| 去重计数 | `COUNT(DISTINCT col)` | 注意 NULL 与空串归为同一组 |

- **每个指标在 `rpt_metric_def.definition_text` 中必须明确写出使用哪一种。**
- 分组维度上的空串/NULL 在 DIM 层统一映射为 `'(未填写)'`，避免报表出现空白分类。
- 字符串拼接一律 `COALESCE(col, '')`，防止整串变 NULL。

## 5. 品类归属口径（实施期发现，**待业务方裁定**）

### 5.1 问题

实测 `film_category` 的分布：

| 每片品类数 | 影片数 |
|---|---|
| 1 | 36 |
| 2 | 561 |
| 3 | 403 |

即 **964 / 1000 部影片属于多个品类**。这不是脏数据，是本 Pagila 分支的真实结构。

后果：按品类统计收入时，一笔 payment 无法唯一归属到某个品类。两种处理各有代价：

| 方案 | 结果 |
|---|---|
| (a) 取 `min(category_id)` 单一归属（**当前实现**） | 各品类金额相加 **= 总收入**，但 964 部影片的收入被归到了其若干品类中的一个，**单品类金额偏低/偏高** |
| (b) 按所有品类重复计入 | 单品类金额"完整"，但各品类相加 **≫ 总收入**（重复计算），不能用于对外披露 |
| (c) 按品类数等分摊（如 3 品类各 1/3） | 相加 = 总收入且分布合理，但引入非整数金额与分摊规则，需额外定义舍入口径 |

### 5.2 当前实现

`dw.dim_film` 取 `min(category_id)` 作为唯一归属，并用 `multi_category boolean` 标记，由 DQ 规则 `FILM_MULTI_CATEGORY`（WARN）统计影响面。

### 5.3 待业务方确认

| 编号 | 待确认 | 备选 |
|---|---|---|
| **B5** | 多品类影片的收入归属规则 | (a) 单一归属 min(category_id)（现状）/ (b) 重复计入（仅限内部分析，禁用于披露）/ (c) 等分摊并定义舍入规则 |

⚠️ **对外披露（C4）的品类维度报表在 B5 裁定前不得发布。**

## 6. 时区口径

- 源表 `payment` 分区边界字面量为 **UTC**（如 `2022-08-01 00:00:00+00`）。
- 实例会话时区实测为 `UCT`（等同 UTC）。
- **所有统计区间参数、分区运维、报表日期一律以 UTC 计算**，禁止依赖会话本地时区。
- 跨界行归属：采用**半开区间** `[from, to)`，边界行归入上界所在期间的**前一期**。

## 7. 金额口径

| 项 | 口径 |
|---|---|
| 源列精度 | `payment.amount numeric(5,2)`（上限 999.99） |
| 汇总列精度 | **一律 `numeric(18,2)`**。实测 `sum(numeric(5,2))` 会自动提升为无约束 `numeric`（全量 67416.51 不溢出），故风险不在聚合而在**汇总表 DDL 照抄源列类型** |
| 币种 | 单币种，不做汇率换算（如需多币种须新增口径版本） |
| 退款/红冲 | 当前源数据无负值 `amount`；若未来出现，需明确是否冲抵同期收入 |
| 除法保护 | 所有比率一律 `NULLIF(denominator, 0)` |

## 8. 同比（YoY）口径

**当前数据仅 2022-01 ~ 2022-07（7 个月），实测 `LAG(amt, 12)` 返回全 NULL → YoY 在现有数据下无法计算。**

口径：
- 预留 `yoy_amount` / `yoy_rate` 列，值为 `NULL`，报表显示「N/A（历史数据不足）」。
- **严禁 `COALESCE(prev_year, 0)`** —— 会产出 `+∞%` / `−100%`，进入披露文件即为灾难。
- DQ 规则 `YOY_BASE_MISSING`（WARN）标记。
- 生产环境若需真实 YoY，**必须补 2021 及更早历史数据**（这是数据问题，不是架构问题）。

---

## 9. 环比（MoM）口径

- 必须先生成「完整月份骨架 × ACTIVE 门店」再 `LEFT JOIN` 事实表，然后 `LAG`。
  **直接对事实表 `LAG` 会在缺月时静默错位**（把 1 月当作 3 月的上一月）。
- `is_complete_period = false` 的期间返回 NULL（见 §3）。

## 11. 闸门语义（不对称，刻意设计）

| 消费者 | 遇 CRITICAL 时 |
